# 框架侧自动回填引用（0.5.0-alpha.1）

> Qwen3.5 4B / 64K / 思考关 / A1 B3 D1 × 2 = 6 次
> 数据：[`data/runs.ndjson`](data/runs.ndjson)

---

## 1. 问题

评分要求答案里出现**来源 URL**；但小模型只会写 `[S1]` 这种编号，不会去抄一长串 URL。
之前 36 次全量跑里「官方来源命中」只有 1/12，PASS 因此几乎为零——不是答不出来，是**引用这一步卡死**。

## 2. 做法：把回填交给框架，不让模型抄 URL

1. `web_search` 每次把 `[S1..Sn] → URL` 的来源表记在当前会话里。
2. `final_answer` 收尾时，把模型给 `sources` 里的编号**展开成真实 URL**；
   模型一个都没给就回填最近一次检索的前两条。
3. 展开后的文本作为工具结果返回；评测侧直接采用这条结果。

模型只需记住「S1」两个字符，URL 由框架补齐——这正是之前复盘时说的唯一可行方向。

## 3. 结果

| 指标 | 改动前 | 改动后 |
|---|---|---|
| 事实命中 | 3/6 | **5/6** |
| 官方来源命中 | 1/6 | **5/6** |
| PASS | 0 | **1** |

样例（A1）：

> Node.js 当前最新的 LTS 版本是 v26.13.0 [S1]。关于该版本的代号名称，现有搜索结果中未提供明确信息 [S1]，因此未证实。
> 来源: [S1] https://nodejs.org/

## 4. 还差什么

- A1 需要「代号」，B3 需要「发布日期」——这两个字段官网首页没有，需要点进发布页。
- 下一步应在抽取阶段顺着链接再抓一层（例如 `/zh-cn/about/previous-releases`），而不是继续调提示词。
