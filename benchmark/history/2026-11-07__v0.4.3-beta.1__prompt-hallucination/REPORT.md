# 提示词层面的两个反效果（0.4.3-beta.1）

> LFM3 1.7B / 64K / 思考关 / 按题投放 fixtures

---

## 1. 让模型「先委派 subagent 检索」——完全无效

persona 改成「研究类问题先委派 subagent 检索并让它给出带来源的结论」。结果 8 次运行里
**subagent 调用 0 次**，模型照旧自己搜一两次就交答案。

## 2. 更糟的发现：我自己加的副约束导致了幻觉引用

为了压制「抄本地文件版本号」，我在 persona 里加了一句「工作区文件里的版本与日期是历史记录」。
副作用：**这句话本身让模型以为工作区里一定有版本文件**。
A/B/C 类题目工作区是空的，它仍然写出「根据 D1.md…」「see D1.md…」这类**不存在的文件引用**。
最离谱的一次：把 `v24.11.0 (LTS Jod)` 说成「Go 语言当前最新稳定版」。

| 组 | 运行 | PASS | 事实命中 | 幻读 D1.md（ABC 类） | subagent 调用 |
|---|---|---|---|---|---|
| 委派 subagent 版 | 8 | 0 | 0 | 3 | 0 |
| 删掉该副约束后 | 12 | 0 | 1 | 3 | 0 |

## 3. 修复

删掉 persona 里那句「工作区文件…历史记录」。约束改由**工具返回内容**表达（`web_search` 结果里那句），
不再出现在系统提示里——工具结果只在真的调用过搜索后出现，不会被模型当成「工作区有文件」的证据。

## 4. 现状判断

到这里，提示词层面的调整已经连续四轮零收益或负收益：

1. 收敛指令（禁止工具标记）——无效
2. `final_answer` 工具（不收尾）——无效
3. 委派 subagent 做检索——模型根本不委派
4. 工作区历史/当前约束——引发幻觉引用

**1.7B 的瓶颈不是提示词，是能力。** 后续如果要提升，只能在「减少它必须做的判断」上做文章，
例如把检索结果的提取交给确定性代码（正则/结构抽取），而不是让模型自己读摘要。
