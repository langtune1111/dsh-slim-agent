# B 类第一次通过：补抓版本跟踪页（0.6.3-beta.1）

> Qwen3.5 4B / 64K / 思考关 / B3 × 3

---

## 1. 问题

B3 要求 **两个** 独立来源（`rust-lang.org` 和 `endoflife.date`），而 Bing-CN 对任何查询
都返回同一批通用结果，永远给不出 `endoflife.date`——这题在结构上无法通过。

## 2. 改动

搜索之后，若查询里能识别出**已知产品**（nodejs / python / rust / go / java / docker / …），
额外抓一次 `https://endoflife.date/<slug>`，把它的版本号与日期作为**新的一条带编号来源**
登记进来源表——这样模型引用时才会带上这个域名。

产品名映射只覆盖常见项，查不到就跳过，不做猜测。

## 3. 结果

| 指标 | 数值 |
|---|---|
| 运行 | 3 |
| PASS | **2/3** |

通过的两次，`official_hits` 同时包含 `rust-lang.org` 与 `endoflife.date`：

> Rust 当前最新的稳定版本号是 1.99.1，发布日期为 2026-10-15。这一结论依据两个独立来源交叉验证…

**这是整条线里 B 类（多源核验）第一次真正通过。**

## 4. 边界

- 只对**已知产品**生效；冷门库名识别不到就不会补抓。
- `endoflife.date` 是第三方站，数据准确性由它自己负责；插件只是把它当作可引用的来源之一。
- 需要联网访问 `endoflife.date`；不通时会静默跳过。
