> Qwen3.5 4B / 64K / 思考关 / 2026-11-14 ~ 15

## 0. 意外发现：题库会腐烂

本来直接跑四组对照，结果第一组前 6 题全 FAIL，连以前能过的 A1/B3 也没过。查答复发现
**模型答的是今天的事实，数据集停在 11-09**：

| 题 | 11-09 冻结值 | 11-14 线上实测 | 那份旧数据跑出来的结果 |
|---|---|---|---|
| A1 Node LTS | v26.13.0 | **v26.13.1**（11-11） | FAIL（答对了今天的版本，被判错） |
| A3 llama.cpp | v0.9.0（11-04） | **v1.0.0**（11-13） | FAIL |
| B3 Rust | 1.99.1 | **1.100.0**（11-12） | FAIL |
| B2 PostgreSQL | 18.6 | **18.7**（11-12） | FAIL（模型答 19.8，是编的） |
| B1 Go | 1.27.3 | **1.27.4**（11-10） | FAIL |
| C1 日期差 | 19 天 | **17 天** | FAIL |

原始证据：`data/rot-evidence-2026-11-14.ndjson`（刷新前那一轮，7 条）。

**冻结快照式的实时题，5 天就烂。** 所以这一轮改成「开跑前用 `refresh_groundtruth.py`
从官方源刷新真值」，on/off 两组共用同一份刷新结果，不偏向任何一侧。

## 1. 四组结果（刷新后）

| 组 | 题数 | PASS |
|---|---|---|
| tuned / versionSources=on | 14 | **6** |
| tuned / versionSources=off | 14 | **6** |
| held-out / versionSources=on | 8 | **2** |
| held-out / versionSources=off | 8 | **2** |

`versionSources: off` 关掉的东西：endoflife 补抓、GitHub release 抓取、多产品官方页、抓取白名单。

## 2. 判定

先写死的判定标准是「tuned 差 ≥3 且 held-out 差 ≤1 → 题库特化」。实际结果：

- **tuned：on 6 / off 6，差 0**
- **held-out：on 2 / off 2，差 0**

也就是说：**在真值新鲜的前提下，那套产品→站点知识表对分数的贡献是 0。**
既没有让已知产品变得更好，也没有帮到未知产品。

之前 PR 里那些「A3 0/2 → 2/2」「B3 2/3」的提升，至少有一部分来自**当时的数据集
与线上事实的差**，不是来自知识层本身；还有一部分来自我改过 A3 的标准答案。

## 3. 三个附带发现

### 3.1 第三方版本源会过期，而且会把模型带偏

B3 是最直接的例子：`endoflife.date` 显示 Rust 1.99.1，而官方 GitHub 已是 1.100.0。
开着知识层时模型被喂了 1.99.1，反而答错；关掉后模型自己搜到 rust-lang.org 答对了。
**给模型补来源，可能是在给它喂过期数据。**

### 3.2 白名单仍然在做实事——通用打分器打不过它

这一轮顺手试了「去掉产品白名单、改成通用打分（降级 CSDN/知乎等聚合站）」。结果反而更差：

| 题 | 通用打分器 | 白名单优先 |
|---|---|---|
| A1 | FAIL（抓了 `nodejs.cn` 镜像，facts 只对一半） | **PASS**（nodejs.org） |
| D1 | FAIL（引了 `blog.csdn.net`） | **PASS**（nodejs.org） |
| B3 | TIMEOUT 180s | 正常 |

所以最终实现是**白名单优先 + 通用打分兜底**（未知产品才不会无处可去），而不是纯通用。
这条也说明：知识层里「去哪儿抓」是有价值的，「第三方事实源」才是没价值甚至有害的那部分。

### 3.3 held-out 两边都是 2/8

只有 SQLite（H-B2，搜索第一条就是官方页）和纯本地任务（H-T1）能过。
Bun / Deno / Terraform / Caddy / Elixir+Zig 这些在搜索后端拿不到官方页的产品，
**开不开知识层都一样失败**——因为它们本来就不在表里。

## 4. 逐题明细

见 `data/` 下 8 个 ndjson。tuned 组的 D1/D2/D3 用的是刷新后补跑的 `r89b_d_on` / `r90b_d_off`
（原始 G1/G2 里那三行是过期真值，不计入）。

## 5. 结论：过拟合是真的，但性质和我一开始想的不一样

| 层 | 是否过拟合 | 证据 |
|---|---|---|
| 架构（收敛/引用回填/工具面/抓取抽取） | **否** | 关掉知识层仍有 6/14、2/8，靠的就是这些 |
| 知识层·站点选择 | **否，而且在做事** | 去掉后 A1/D1 直接退到镜像站和 CSDN |
| 知识层·第三方事实源 | **是，且有害** | endoflife 的旧版本反而让 B3 答错 |
| 评测口径 | **是** | 冻结答案会腐烂；我还改过 A3 的标准答案 |

真正需要修的不是「删掉硬编码」，而是：**实时题必须每次刷新真值**（已做），
**第三方事实源要能和官方源对账**（下一步），以及**不许再用改标准答案的方式提分**（已写进纪律）。
