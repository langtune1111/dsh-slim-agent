## 0. 为什么要换实验

上一轮（180 次）留下的唯一确定结论是**引用合规全线为 0**：模型能搜到官方页面，
但不会把 URL 写回答案；而收敛性差异（完整 slim 74 s vs 无子代理组 26.8 次搜索后超时）
是产品可用性的真实信号。

所以这一轮只做一件事：**把"引用"从模型的自发行为变成可测量的受控变量**，
看它能不能被一条提示词约束拉起来，以及代价是多少。

**不做**：常规补跑（剩余 9 题）、4K 块、架构新增功能。

## 1. 你指出的公平性问题（这一版必须修）

上一轮的对照组是这么设置的：

| arm | 上一轮的搜索能力 |
|---|---|
| A 极简 / B 标准 | **完全没有搜索工具** |
| G pi | **完全没有搜索工具** |
| C/D/E/F slim | 有（内置 DDG→Bing→Wikipedia） |

这确实不公平：等于让 slim 带着武器跟赤手空拳的打，赢了也说明不了架构好坏。
**上一轮报告里"A/B/G 全灭"s 的结论因此只能说明"没有搜索就做不了实时事实题"，不能用来评价架构。**

### 1.1 这一版怎么修

**原则：每个 arm 都用"自己的渠道"获得搜索能力，但搜索源、可搜范围、结果条数、输出格式全部对齐。**

| arm | 搜索由谁提供 | 说明 |
|---|---|---|
| A 极简 | DSH 原生 `web_search` 工具（`@deepseek-ai/dsh-tool-web`） | 用它自己的工具面，不注入 slim 的任何东西 |
| B 标准 | 同上 | 同上 |
| C slim 无子代理 | slim 内置 `web_search` | 产品自身实现 |
| D slim 完整 | slim 内置 `web_search` | 产品自身实现 |
| G pi | pi 扩展注册的 `web_search` 工具 | pi 自己的扩展机制 |

**唯一共享的东西是一份搜索后端**（`bench2/search-core.mjs`）：
同一个 Bing 端点、同一个 User-Agent、同样取前 5 条、同样的 `[来源标签] [标题](URL) (年份) - 摘要` 输出格式。

> ⚠️ 诚实说明：slim 的搜索代码是内置在 `preset-core.mjs` 里的，**不可能逐字节与共享模块相同**。
> 我们能对齐的是"同一端点 + 同样条数 + 同样输出模板"，剩余差异（例如 slim 会做域名启发式分类）
> 会在报告里显式列出，并作为"产品价值"而非"测量误差"来讨论。

### 1.2 DeepSeek 搜索 API 仍然是红线

四层禁令沿用上一轮（插件层禁用 / 凭据层剔除 / 代码层只用 Bing 链 / 运行时校验 `engine` 字段），
一旦发现 `host` 或 `deepseek` 引擎，该 arm 数据作废。

## 2. 自变量：引用约束

**只改任务提示词，不改任何产品代码**，这样七个 arm 的改动完全对称。

| 变体 | 提示词后缀 |
|---|---|
| **V0 无约束**（对照） | 与上一轮完全相同的原始问题 |
| **V1 强制引用** | 「回答中**每一个事实后面必须紧跟 `[来源: URL]`**；找不到来源的内容一律写「未证实」，不要给出来源以外的推断。」 |

> 选择在提示词层做，而不是改 slim 的工具输出，原因：改工具输出只对 slim 生效，
> 对照组没法同等施加，会重新引入不公平。

同时记录一个**非自变量的副产品**：slim 的 `web_search` 返回里本来就带 `[来源标签]`，
所以 V1 对 slim 的边际成本可能更小——这一点会在报告里单独讨论，而不是当成混杂因素掩盖掉。

## 3. 因变量与判据

主指标只有四个，全部可机器判定：

| 指标 | 定义 |
|---|---|
| **Citation Precision** | 答案里的 URL 中，属于官方域名白名单的比例 |
| **Citation Coverage** | `required_facts` 里，每个事实后面是否都跟着一个 URL（按事实逐个判定，给出 n/m） |
| **Answer Accuracy** | `required_facts` 命中率 |
| **Fabricated Citations** | 出现 404/无法解析/域名不在 dataset 白名单的 URL 次数 |

辅助：端到端耗时、LLM 请求数、搜索调用数、终态（FAIL / TIMEOUT / BUDGET_INVALID）。

**判定口径**：`Citation Coverage` 是这一轮的主指标，因为它才直接回答"约束有没有用"。
`PASS` 仍然保留（事实全中 + 至少一个官方 URL + 搜索调用合规），但只作辅助。

## 5. 运行规模

| 维度 | 取值 |
|---|---|
| arm | A、B、C、D、G（**去掉 F**：`task_complete` 的影响上一轮已有结论，不再重复） |

## 7. 验收口径

1. **V1 的 Citation Coverage 必须显著高于 V0**，否则结论是"提示词约束对 1.7B/4B 无效"，这本身也是有效结论，照写。
2. 若 V1 把耗时抬高 50% 以上，需在报告里明确"引用约束的成本"。
3. 任何 arm 出现 `host`/`deepseek` 引擎 → 该 arm 作废。
4. `BUDGET_INVALID` 比例 > 10% 的 arm 不进主表。
5. 所有 80 条原始记录入 `data/`，不挑选。
