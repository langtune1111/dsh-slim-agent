## 1. 摘要

测试本地小模型（LFM3 1.7B / Qwen3.5 4B）在 8K 上下文下，能否靠 **agent 自身具备的搜索能力**
完成"实时事实检索 / 多源核验 / 多跳推理 / 本地+联网结合"四类任务，并用消融开关分别隔离
**搜索**、**子代理**、**收尾工具** 三项设计的贡献。

七个 arm 全部跑各自的代码路径，不给任何一组外挂搜索；DeepSeek 搜索 API 全程禁用。

> 结果：**待跑**。填入后本节须包含：七组总通过率、两模型分开、8K/64K 对比、四类分类通过率、
> 引用准确率与来源覆盖率、主/子代理 token 拆分、超纲题 0/x 记录。

## 2. 题目总表（12 主线 + 3 超纲）

**出题纪律**：答案一律来自 `benchmark_date - 14~30 天`内发布的官方一手页面；
出题时同步冻结快照（URL + 抓取时间 + `sha256` + 关键段落），实验期间不允许页面漂移。
**具体数值、版本号与 URL 在 P0 阶段一次性冻结进 `dataset.json` 与 `sources/`**，
本文件只固化"问什么、怎么判"——这样即使官方改版，作废重出的也只是 dataset，不是判据。

### A 类 · 实时事实检索（3 题）

| ID | 问什么 | 必须答对 | 判据 |
|---|---|---|---|
| **A1** | 某个近期发布的开源软件/推理框架，**当前最新稳定版**是哪个版本、发布日期是哪天 | 版本号 + YYYY-MM-DD | 版本与日期均精确匹配；必须给出官方 release 页 URL |
| **A2** | 某个近期公布的**硬件规格或技术参数**（如某卡显存/带宽/支持的数据类型） | 具体数值 + 单位 | 数值容差 0；必须引用官方 spec 页 |
| **A3** | 某个近期发生的**技术事件**（发布/并购/标准通过），时间、主体、结果各是什么 | 日期 + 主体 + 结果 | 三项全中；`min_sources = 1`，且来源为官方公告 |

> 三题共用规则：`must_call_search = true`；用旧知识答对也算 `FAIL`（记录 `NO_SEARCH`）；
> 出现"我查到…"但无 URL → `CITATION_UNSUPPORTED`。

### B 类 · 多来源交叉核验（3 题）

| ID | 问什么 | 必须答对 | 判据 |
|---|---|---|---|
| **B1** | 同一项参数在**官方文档**与**第三方技术文章**里是否一致；若不一致以哪个为准 | 正确取值 + 明确指出不一致点 | `min_sources = 2`，其中至少 1 个官方域名 |
| **B2** | 某旧版本文档里的一条说明，在**当前版本**是否已失效 | 失效/仍有效 + 替代说明 | 必须引用新旧两份材料 |
| **B3** | 对同一技术问题，两个**相互独立**的官方来源是否互相印证 | 印证/冲突 + 依据 | `min_sources = 2` 且域名不同 |

### C 类 · 多跳推理（3 题）

| ID | 问什么 | 必须答对 | 判据 |
|---|---|---|---|
| **C1** | 从两个官方页面分别取参数 A 与 B，按给定规则算出结果 | 中间量 + 最终值 | 中间量与最终值均对；`min_sources = 2` |
| **C2** | 某功能**首次出现**于哪个版本、哪一天 | 版本 + 日期 | 需引用 changelog 或 release notes |
| **C3** | 某技术方案在什么条件下适用、有什么硬限制 | 适用条件 + 限制各至少 1 条 | 结论必须能被所引来源支持 |

### D 类 · 本地 + 联网结合（3 题）

题面附带一份**本地旧文件**（`fixtures/D*.md`，实验前冻结），任务是"读本地 → 联网核对 → 说差异"。

| ID | 问什么 | 必须答对 | 判据 |
|---|---|---|---|
| **D1** | 本地记录的是旧参数，最新官方值是多少、差在哪 | 旧值 + 新值 + 差异点 | 必须出现 `read` 与 `web_search` 两类调用 |
| **D2** | 本地项目的某项配置按最新官方文档是否已过时 | 结论 + 依据 | 同上；`STALE_SOURCE` 与 `CITATION_UNSUPPORTED` 分开记 |
| **D3** | 按本地需求描述，联网找适配方案并说明兼容性与限制 | 方案 + 至少 1 条限制 | 同上；方案必须来自官方来源 |

### X 类 · 超纲题（3 题，预期全灭，不计入 Overall Pass Rate）

| ID | 为什么超纲 | 期望观察到的失败类型 |
|---|---|---|
| **X1** | 需读 3 篇官方文档 + 1 篇 changelog，跨 4 源比对同一 API 三次变更 | `TOOL_LOOP` / `MULTISOURCE_WRONG` |
| **X2** | 需先算中间量，再去官方表反查条目（两跳 + 数值换算） | `SEARCH_OK_NO_UNDERSTANDING` |
| **X3** | 需识别某官方页面已被新版取代（旧链接仍 200 但内容过期） | `STALE_SOURCE` / `CITATION_UNSUPPORTED` |

> X 类单列成表，**0/9 也是有效结果**——它标出的是当前模型规模的能力天花板，不是插件缺陷。

## 3. 判据（每题共用部分）

```
PASS = 核心事实正确
     ∧ 日期/版本/数值正确
     ∧ 至少调用过一次 web_search（A 类除外）
     ∧ 引用 URL 真实可达（HEAD 200）且属于官方域名白名单
     ∧ 未使用过期信息
     ∧ 没有编造来源
     ∧ 正常产出最终文字答复
```

分项指标：`Answer Accuracy` / `Search Compliance` / `Citation Precision` /
`Citation Coverage` / `Freshness Accuracy` / `Overall Pass Rate`。

无效运行不计入分母：`max_tokens < 256` → `BUDGET_INVALID`；prompt 超过 `contextWindow` → `CONTEXT_INFEASIBLE`。

失败类型枚举见 [PLAN.md §7.4](PLAN.md)。
