## 一、 核心设计思路：改变 Agent 的工作方式

大模型可以凭借千亿参数和海量上下文窗口硬吞复杂任务，但小模型不一定需要走同一条路线。

我们将小模型 Agent 能力增强总结为一个公式：

$$\text{更高的有效 Agent 能力} = \frac{\text{极简主代理 (4K/8K)} + \text{任务委派 (子代理隔离)} + \text{主动联网搜索 (获取外部知识)}}{\text{上下文与执行预算管理}}$$

这不是简单的 Prompt 压缩，而是从底层改变 Agent 的协作与调度方式：

```
                用户输入复杂任务 (例: 调研并选型一个陌生的技术方案)
                                │
                                ▼
┌────────────────────────────────────────────────────────────────────────┐
│ 主代理 (Main Agent): 1.7B ~ 8B 本地小模型                               │
│ 4K / 8K 短上下文 · 固定开销压减至 600~1000 tokens · 仅暴露 6 个基础工具     │
│   read        edit        bash        web_search       task_complete   │
└───────────────────────────────────┬────────────────────────────────────┘
                                    │ 遇到多网页阅读 / 深度代码分析
                                    ▼ 委派子代理 (subagent)
┌────────────────────────────────────────────────────────────────────────┐
│ 子代理 (Subagent): 独立执行环境                                         │
│ 拥有完整研究工具面 (web_search, web_fetch, read, bash...)              │
│ 负责多网页阅读、交叉核实、提取证据链 · 任务完成后整体销毁                │
└───────────────────────────────────┬────────────────────────────────────┘
                                    │ 仅回传提炼后的三段式结构化报告
                                    │ 【已确认结论】+【未验证疑点】+【建议下一步】
                                    ▼ 原始网页正文永不进入主上下文
┌────────────────────────────────────────────────────────────────────────┐
│ 主代理整合提炼结论，完成代码编写与最终回答 (避免 Context Overflow)        │
└────────────────────────────────────────────────────────────────────────┘
```

## 二、 三大技术柱石

### 1. 极简主代理：让小模型只做自己最擅长的事情
传统 Agent 往往将几十个复杂工具（搜索、读取、写入、Git、数据库、MCP、各类插件）一股脑全塞给主模型。对于 4K/8K 上下文的小模型来说，光是理解长篇累牍的工具定义就会消耗数千 Token，且极易引发工具误选与格式解析崩溃。

DSH Slim Agent 将主代理严格收窄为 **6 个核心基元工具**：

| 工具 | 职责 | 为什么这样设计？ |
|---|---|---|
| `read` / `edit` | 文件读取与单处精确修改 | 由 `@deepseek-ai/dsh-tool-fs` 提供，受宿主工作区沙箱约束 |
| `bash` | 单条命令执行 | 默认受 `ctx.subprocess.spawn` 监管，绑定当前工作区并写审计日志 |
| `web_search` | 联网获取线索 | 只回传 3–5 条 `[来源标签] [标题](URL) (年份) - 一句话摘要`，**从不回网页正文** |
| `task_complete` | 显式完成任务 | 显式终止原语，触发 `exec.concludeTurn()`，根除小模型“无话找话”死循环 |
| `subagent` | 结构化任务委派 | 启动物理隔离子代理，只接收提炼结论 |

> **核心原则**：不是强求让小模型变得“更聪明”，而是尽可能剥离无关干扰信息，降低认知负担。

### 2. 独立子代理：把复杂任务拆出去
当用户提出复杂调研需求（例如：“调查 2026 年最新发布的开源 Agent 框架，对比技术架构与显存开销”）：
- **传统方式**：主模型亲自阅读每一个网页全文，几篇之后 8K 上下文直接打满崩溃；
- **Slim 方式**：主模型拆解目标并委派子代理，子代理在独立上下文里完成检索、阅读与比对，**任务完成后整个子会话销毁，只将精炼结论送回主模型**。

同时内置**并发闸门（默认并发 = 1）**：消费级显卡（6G–12G）上严格串行分时复用显存，绝不引发多代理并发导致的显存 OOM 崩溃。

### 3. 主动联网搜索：小模型打破知识壁垒的关键
小模型最大的软肋是参数规模有限、训练数据截断、缺乏实时世界知识。
**传统思路是把模型换大，而我们的思路是让模型学会主动查资料**：
- **RAG 不一定需要百亿大模型，Agent 也不应该完全依赖模型内部记忆**；
- 模型通过轻量 `web_search` 获取实时线索，通过子代理深入研读权威文档与源码；
- 内置**来源性质染色**（`[源码仓库]`、`[文档站]`、`[社区讨论]`、`[百科]`）与年份提取，让小模型直接依据高置信度标签决策。

## 三、 核心概念：“能力密度” (Capacity Density)

普通 Agent 往往追求：“能提供多少工具？支持多复杂的协议？”  
DSH Slim Agent 关注的是：**每 1,000 Token 上下文，能够支持模型完成多少有效工作？**

$$D = \frac{\text{成功完成的有效任务数}}{\text{消耗的主代理上下文 Token} / 1000}$$

| 维度 | 传统全功能 Agent | DSH Slim Agent |
|---|---|---|
| **工具定义占用** | 2,500 ~ 5,000+ tokens | **600 ~ 1,000 tokens**（留足 85%+ 空间给任务） |
| **网页正文处理** | 直接平铺进主窗口，极易冲垮窗口 | **子代理物理隔离处理**，只回传精炼三段式 |
| **信息检索机制** | 依赖模型内部死记硬背 | **主动联网检索**实时事实与权威线索 |
| **任务拆分机制** | 取决于单体大模型推理深度 | **结构化委派**，大任务化小 |
| **短上下文适应** | 8K 极易溢出，4K 无法启动 | **专为 4K / 8K 短窗口量身打造** |

## 四、 演示场景：4B 模型在 4K 极限上下文下的开源项目调研

设想一个极具说服力的演示用例：**让本地 4B 模型在 4K (4,096 tokens) 极限窗口下，调查一个它从未见过的全新开源项目**。
- **任务目标**：
  1. 搜索项目最新版本与发布动态；
  2. 阅读项目 README 与核心架构；
  3. 检索近期的真实 issue 与社区反馈；
  4. 总结项目优缺点并附来源链接。
- **实测表现**：
  - **原生 Agent**：在第 2 轮检索网页正文注入后，上下文直接超过 4,096 tokens 发生 **Context Overflow 失败**；
  - **Slim Agent**：主模型固定开销仅 ~650 tokens，通过委派子代理完成所有网页长文研读与比对，主代理仅接收到数百 tokens 的结构化结论，在 4K 极限窗口下**从容稳定通关**！

## 六、 ⚙️ LM Studio 本地部署建议配置

1. **加载模型**：推荐 `LFM-3 1.7B Q5_K_M`（极小基线）或 `Qwen3.5 4B Q4_K_M`（主力）；
2. **锁定上下文**：在参数面板中将 **Context Length** 手动设为 **`8192`**（亦可挑战 `4096` 极限短窗口）；
3. **显存加速**：将 GPU Offload 拉满（4B Q4KM 权重约 2.6GB，8K KV Cache 约 0.8GB，合计仅 ~3.8GB，6GB 显卡即可满速运行）；
4. 启动 Local Server，DSH 端通过 OpenAI 兼容端点（`http://127.0.0.1:1234/v1`）接入。

## 八、 🛡️ 安全、沙箱与已知限制

- **Shell 沙箱透明性**：`bash` 工具默认配置为 `bash: 'sandbox'`，直接调用宿主 `ctx.subprocess.spawn` 启动独立进程并绑定工作区 `cwd`。在无沙箱服务的宿主上会坚决报错拒绝执行，绝不假装沙箱隔离；若需本地执行请显式配置 `bash: 'local'`（受破坏性命令正则拦截与审计日志保护）。
- **DSH 0.2.x 原生支持**：已在 DSH 0.2.1-rc.5 原生桌面环境下联调通过，完整支持最新的 `startActivation({ provider, label, request, signal, delivery: 'parent' })` 接口。
- **并发锁零死锁保证**：子代理调度采用全局单层刚性 `try...finally { sem.release() }`，无论任务取消、异常抛出还是网络超时，信号量 100% 安全归还。
- **配置防损坏**：安装器具备单边残缺标记检测与备份失败硬熔断，写盘前写入临时文件原子替换，绝不损坏用户原有的 `cordis.patch.yml`。
