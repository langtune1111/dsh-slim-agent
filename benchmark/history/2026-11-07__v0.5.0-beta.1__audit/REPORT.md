# 0.5.0-alpha.1 审计报告（0.5.0-beta.1）

> 审计对象：`0.5.0-alpha.1`（框架侧自动回填引用）
> 审计方式：通读新增代码 + 检查资源生命周期 + 复核评分口径

---

## 1. 修掉的问题

### A1 来源表无界增长

`lastSources` 是 `Map`，每个新会话（工作目录/会话 id 不同）都会塞一条，桌面端是长生命周期进程，
**用一年就是一个几百条的 Map**。已改为「最近 32 个会话」，并在 `session/disposed` 时删除。

### A2 会话销毁时没清来源表

预算计数器清了，来源表没清。已一并清理。

## 2. 审计中发现但**没有改**的口径问题（需要记住）

### C1 回填引用会让「官方来源命中」这一指标变松

框架把最近一次检索的前两条 URL 回填到答案里。这意味着即使模型没真正引用，
评分里的 `ok_cite` 也会满足。**这是有意的产品行为**（框架记录的确实是它读过的页面），
但它削弱了这个指标对「模型是否读过来源」的证据力。

结论：从 0.5.0 起，**只有 `facts_ok` 是可信的能力指标**，`official_hits` 只能说明「框架给了来源」。

### C2 抓取只抓首页，拿不到细节字段

A1 要「代号」、B3 要「发布日期」，官网首页没有这些。当前实现只抓首条，够不着。
这属于下一步功能（顺着链接再抓一层），不是本轮缺陷。

### C3 `fetchExcerpt` 在工具调用栈里同步等待

最坏情况给单次工具调用增加 8 秒。已受 `fetchTimeoutMs` 约束，但会推高整体耗时（实测均值约 118 秒）。
若要压时间，可把抓取改成「先返回摘要、后补抓取」，代价是工具协议变复杂——暂不做。

## 3. 复核结果

- 单测 36 项全过（含 SSRF 用例）
- 抓取路径：协议白名单、私网拒绝、类型限制、体积上限，四项都在
- 收敛路径：`convergeFinalOnly` 与 `final_answer` 互斥检查在（没有出口就不收敛）
- 计数路径：按 `session.id` 分桶、每轮清零、会话销毁清理

## 4. 结语

alpha 的能力改动（自动回填引用）本身没有发现功能缺陷，两处资源问题已修。
本轮把「引用」这条链路彻底打通：从「模型必须自己抄 URL」改成「框架替它补全」。
